# Последовательная работа команды

Общая память — файлы репозитория. Не предполагайте существование прошлого чата.
Ветки и одновременное редактирование не являются частью workflow.

Человек следующего этапа после подтверждения предыдущего push выполняет:

```sh
git checkout main
git pull --ff-only origin main
git status --short
```

`main` подтверждена локально на bootstrap; если правила upstream изменились,
человек сначала проверяет default branch. При грязном дереве сохранить и
разобрать изменения, а не применять reset/clean.

1. Прочитать документы в порядке AGENTS.md.
2. Запустить `python scripts/verify_core.py` до редактирования.
3. Передать Codex промпт своей роли: `02-frontend.md`, затем `03-backend.md`,
   затем `04-integration.md` из `.codex/prompts/`.
4. Выполнить scope роли и проверить diff, core и свой слой.
5. Обновить README, PROJECT_STATE, дописать PROGRESS, создать новый handoff.
6. Человек проверяет `git diff --check`, `git status --short`, содержимое
   новых untracked файлов и тесты; делает осмысленный commit и push.
7. Следующий участник начинает только после подтверждения успешного push.

При rejected push или неожиданном commit: не force push, остановить передачу,
проверить историю и согласовать состояние. Человек делает безопасный fetch/
inspect и `pull --ff-only` только после сохранения своей работы; при
расхождении веток не запускать автоматический merge/rebase.

Codex не делает Git-операции изменения истории или ветки. Placeholder commit
не является настоящим hash. Связь handoff с commit хранить в новом состоянии
или Git-истории, не переписывая завершённый handoff.
